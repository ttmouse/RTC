# RTC 能力问题清单 — CHALLENGER

> 定位：这份清单不按功能域平铺，专门找「按正常套路扫会漏掉」的那一类问题。
> 每条都写了「为什么容易漏」——两份清单合并时，只有这边有、那边没有的条目必须被显式讨论。
> 全部条目用业务语言描述：用户在哪个界面、做什么操作会触发。

---

## 视角一：真实事故的同类推广

| 编号 | 能力问题 | 产品入口 | 风险 | 它推广自哪一条 / 为什么规格方容易漏 |
|---|---|---|---|---|
| C-001 | 用户对着麦克风说话，但麦克风被系统或硬件（键盘静音键、菜单栏静音、输入音量拉到 0）关掉了：应用还在录、回调还在跑，只是送进来的全是静音。录完整场一个字也没有，状态区全程写「识别中」。 | 主界面底部状态区 + 点录音按钮 | R3 | 推广自 UX-14 的「看起来还开着」。UX-14 把判据刻意定成「回调停没停」并写进了规范，规格方会把它当成已闭环，不会再去问这个判据的盲区：回调没停、但送的是空气。 |
| C-002 | 录音中途识别服务掉线（服务被重启、端口被别的程序占走）：界面继续写「录音中」，只有一次 5 秒的提示说「恢复前只保留最近 10 秒」，此后每一句都在悄悄丢。 | 主界面状态区 + 录音中 | R3 | 推广自 UX-14 的「连接看起来还开着」。规格方会认为「断线重连已有自愈」（UX-14 顺带修了迟到消息），不会问「自愈失败的这十几秒里用户的话去哪了、界面说了没有」。 |
| C-003 | 识别出的那句话明明显示在列表里了，却没写进记录文件（磁盘写满、数据目录被移走、目录不可写）。用户当场看得见，重开应用这句话消失。 | 主界面列表 + 录音中 | R3 | 推广自 UX-13 的「提示自己悄悄失败」。没人把「保存失败」当成提示失败的一种——它不报错、不弹提示，界面和成功时一模一样。 |
| C-004 | 白板「AI 会议内容」这一档，编辑器起不来时正文区看起来和「还没有内容」一样。用户以为模型还没生成，一直等，实际是编辑器坏了。 | 会议白板 · AI 会议内容档 | R2 | 推广自 UX-5（空态露出编辑器骨架）与 UX-13（失败长得像没发生）。UX-5 记的是「空着时露出内部骨架」，没有人问「失败时露出的空壳，用户分不分得清」。 |
| C-005 | 本机模型服务「在跑」不等于「能识别」：模型文件缺失或加载失败时服务仍在、探测通过，主界面说「就绪」，点录音进去，整场一个字不出。 | 主界面状态区 + 设置页识别方式 | R2 | 推广自 UX-11。修法把「本机模型服务端口可达」当成了「本地识别可用」的等价物，规格方会沿用这个等价物，不会单独问「可达但不可用」这一格。 |
| C-006 | 云端引擎（百炼）没有「能不能用」的状态：Key 失效、欠费、网络不通时，状态区照样「就绪」，点录音进「识别中」，整场不出字，也没有「为什么」和「怎么办」。 | 主界面状态区 + 设置页识别方式 | R2 | 推广自 UX-11/UX-12。那两条只处理了本地引擎的第二个服务；云端引擎被默认成「配了就通」，而设置页里对它的检查只有一个要用户手动点的「测试」按钮。 |
| C-007 | 还有一批「报了问题但没有下一步」的位置：麦克风不可用、更新下载失败、清除历史失败、外部写入被拒。用户看到一句话，不知道该干什么。 | 状态区 / 更新横幅 / 设置页 / 白板 | R2 | 推广自 UX-12 的产品原则补段（说出了问题就要给出下一步）。UX-12 修的是一条具体路径，规格方容易把它当成「异常提示规范已全面落实」，不再逐条点验。 |
| C-008 | 应用不在最前面的时候（用户切到别的软件），「最新状态」是旧的：外部 AI 刚写进白板的正文、刚变的服务状态，用户看不到，回来看到的还是几分钟前那一版。 | 会议白板 / 主界面状态区 | R2 | 推广自 UX-8（后台在干活，界面说「什么都没有」）。UX-8 只讲了「正在生成」这一种后台状态，没推广到「后台刚写完」「后台又挂了」这些同样只在别处发生的变化。 |
| C-009 | 提示渲染出来了，但出现在用户当时看不到的那个窗口：白板的「你有未保存的改动」只在白板窗口里，而用户在另一块屏操作主界面。 | 会议白板 / 主界面 | R2 | 推广自 UX-13 的「写了看不见」。UX-13 讲的是提示根本没渲染出来；没人问「渲染出来了，但用户在另一个窗口 — 这算不算没提示」。 |
| C-010 | 系统省电或窗口被挡住时，应用内部的计时会跳、会少算：本次录音时长、空闲时显示的本地服务运行时长都可能偏短，用户拿它当会议长度。 | 主界面底部状态区 | R1 | 推广自 UX-14 认「睡过一觉」靠的是自己的计时跳变。规格方会接受「启发式」这个说法，不会反过来问「同一套计时跳变会让时长这个数字说谎」。 |
| C-011 | 同一件事有三个数：标题栏的今日记录总数、白板标签上的计数、历史列表的条数。三个数各算各的，并排看不出来它们不可比。 | 标题栏 / 会议白板标签栏 / 主界面列表 | R1 | 推广自 UX-7（两个标签的数字单位不同）。UX-7 只在白板内部判了一次，没人把它推广成「跨界面的同名数字要能被对上」。 |
| C-012 | 录音中用户插上耳机（比如 AirPods），系统把声音切到耳机，RTC 还在用原来的麦克风（旧设备并没有完全断开）。用户对着耳机说话，录到的是空房间。 | 主界面 + 录音中 | R2 | 推广自 UX-14 的「麦克风句柄失效」。修法判的是「回调停没停」和「音轨有没有结束」，而设备被换走时这两条都不一定成立——回调照跑，只是录的来源不对。 |
| C-013 | 标题栏「今日记录总数」的数字一有新记录就变宽，图标和文字整体位移；用户正要点统计页时会被推走、点空。 | 标题栏 | R1 | 推广自 UX-6（标签宽度随内容跳动）与 UX-9（按钮忽隐忽现）。规范第 3 条只写了「列表不许跳」，规格方不会把「不跳」推广到标题栏这种一像素都不该动的区域。 |

## 视角二：多来源同时改同一份数据

| 编号 | 能力问题 | 产品入口 | 风险 | 它推广自哪一条 / 为什么规格方容易漏 |
|---|---|---|---|---|
| C-014 | 命令行入口（rtc config set）改配置时是「把整份文件读出来、改一处、整份写回」，和界面里的配置写入不在同一条队上。录音时界面每秒都在写配置，两者一交错就互相吞掉：用户在命令行设的项、或界面刚记下的录音时长，过一会儿变回旧值。 | 命令行 / 设置页 / 录音中 | R3 | 产品原则第 6 条明说「外部工具会同时改配置」，工程落点写着「合并放到服务端串行做」——规格方会认为冲突已解决，不会发现那只护住了「界面内部」，护不住命令行和外部助手。 |
| C-015 | 外部 AI 助手直接编辑配置文件（这是被鼓励的用法）时，与界面的写入同样会打架，而且双方都毫无察觉。用户会遇到「明明改过又变回去了」。 | 外部 AI 助手 / 设置页 | R3 | 同 C-014，且「文件即接口」一直是当作优点在讲的，没人把它当成一把双刃剑来问代价。 |
| C-016 | 语音指令页开着的时候，外部 AI 改了同一份指令文件：页面上还是旧的那张表，用户看着旧数据做决定、然后点保存。他以为屏幕上就是现在的值。 | 语音指令页 | R2 | 界面规范只保证了「保存不会抹掉外部改动」（写入方向），没人保证「打开着的那一刻读到的就是最新的」（读取方向）。规格方扫「不许覆盖」这条时会顺着规范走。 |
| C-017 | 外部 AI 删掉的一条口令，用户随后编辑并保存了同一块（他并不知道它被删了）：那条被悄悄「复活」。 | 语音指令页 | R2 | 「保存只提交改动过的条目」这条约束解决的是「不覆盖别人」，删除语义只在页面自己的快照内部成立。规格方会认为删除已经显式列出、没问题。 |
| C-018 | 用户在设置页改了设置、还没点保存，同时又用全局热键或底栏开关改了同一个开关：两处的值不同步，保存时以页面里的旧值为准，用户看到的和实际生效的不一致。 | 设置页 / 底栏开关 / 全局热键 | R2 | 底栏开关是「改了立刻生效」，设置页是「保存才写」——两套心智各自看都对，规格方分开读时不会发现它们共用同一份设置。 |
| C-019 | 白板正文：用户正在编辑（停手一会儿才自动保存），外部 AI 恰好在两次保存之间写入。用户的下一次保存把外部刚写的内容整篇盖掉，而且用户自己完全不知道。 | 会议白板 · AI 会议内容档 | R3 | 这条在方案文档「还没做完的」里用工程语言记着（自动保存不检查磁盘是否被改过），读产品文档的规格方会漏；就算读到，界面这一半也没人写：冲突提示只在白板窗口里。 |
| C-020 | 外部 AI 用「整篇替换」写白板正文时，用户之前手写的段落被永久抹掉。提醒只出现在命令行的输出里（给助手看的），用户界面上一个字都没有。 | 会议白板 · AI 会议内容档 | R3 | CLI 有 stderr 提醒，容易被当成「已经提示过了」；但提示的对象是外部助手而不是用户，而用户是唯一会因此受伤的人。 |
| C-021 | 外部 AI 给「前一天那场会议」补写内容时，会把白板当前打开的那一场切走。用户正在开着今天这场会，屏幕上突然变成昨天的内容。 | 会议白板 | R2 | 「写入会把当前场次切过去」这个副作用只有读代码才看得见；产品文档写的是「外部写完面板自己重读」，规格方会把它读成一个纯粹的好行为。 |
| C-022 | 命令行和白板面板对「一场会议从几点算起」用的是两套切分规则。外部 AI 照着命令行给的场次写进去，用户面板上选中的可能是另一场，写完看不见，双方都以为成功了。 | 命令行 / 会议白板 | R2 | 创新清单把它记成「同一段逻辑写了两遍」的维护问题，没人把它翻译成用户看到的那一幕：写完了、界面上没有。 |
| C-023 | 识别结果会自动写进系统剪贴板。用户中途复制了一段别的内容准备去粘贴，下一句识别把它顶掉，用户接着粘贴就粘错了东西。 | 主界面 + 录音中 | R2 | 「点某行复制」「选中即复制」是规范第 5 条明确保留的能力，没人问它和「自动粘贴往剪贴板写字」抢同一块剪贴板时谁赢、用户会不会被坑。 |
| C-024 | 白板正文同时存在两个「存放地」：程序用来展示的那份，和给人看的文档文件。用户改了后者（这是最自然的做法），白板毫无反应，改动像掉进黑洞。 | 数据目录里的白板文档 / 会议白板 | R2 | 产品原则第 3 条「每个状态只能有一个真实来源」一直被用来讲状态显示，没人拿它检查「同一份内容存了两处、用户改哪一处才算数」。 |

## 视角三：状态说谎

| 编号 | 能力问题 | 产品入口 | 风险 | 它推广自哪一条 / 为什么规格方容易漏 |
|---|---|---|---|---|
| C-025 | 清除历史之后，主界面列表、统计页、白板逐字稿三处是不是同时变了？只要有一处还停留在旧数字或旧内容上，用户就分不清「到底清干净没有」。 | 设置页清除历史 → 主界面 / 统计页 / 白板 | R2 | 破坏性操作在清单里通常按流程检查（有没有二次确认、有没有写「不可恢复」）；「做完之后各界面是否一致」这一层没人问。 |
| C-026 | 语音指令在应用里改完，要重开口令页或重启应用才生效；外部 AI 改完之后更是无声无息。用户说出口令没反应，分不清是自己配错了还是应用还在用旧的。 | 语音指令页 / 主界面说话 | R2 | 指南里写着「修改后重新打开或重启」，那是写给外部助手的操作说明，不是界面给用户的交代。规格方会把它当成已记录。 |
| C-027 | 白板存着三样东西（会前定义、分析结果、正文），界面上只看得到正文。外部 AI 只写了分析没写正文时，白板上什么都不说，用户以为它根本没干活。 | 会议白板 | R2 | 文档自己写着「只写 analysis，白板不会变」——规格方容易把它读成一条设计意图（写在文档里了）而不是一条体验问题（用户会以为失败）。 |
| C-028 | 「用不了的引擎直接不显示」：引擎可用性是异步问来的，问不到的时候某个引擎会凭空消失，用户以为自己装的模型丢了。 | 设置页识别方式 / 底栏引擎下拉 | R1 | 规范把「不显示」定成了正确做法（用来批评「灰着放那儿」），没人反过来问「看不到是不是另一种假状态」。 |
| C-029 | 麦克风权限被系统收走（用户在系统设置里改了）时，应用运行中不会主动发现，要等下次点录音才知道。 | 主界面 | R1 | 权限被当成一次性的启动检查，规格方按「启动时检查过了」这条走。 |
| C-030 | 自动粘贴开关写着「开」，但系统辅助功能权限被拒或被回收时字根本出不去。「最近一句去哪了」那一格只有三种说法（粘了 / 没粘因为不在名单 / 没粘因为认不出目标），没有「因为没权限」。 | 底栏提示格 / 主界面 | R2 | 规范花了大篇幅修「没粘要说话」（真实事故），但它只枚举了两种「没粘」的原因，第三种被漏在枚举之外。 |
| C-031 | 「已是最新版本」和「检查更新失败」共用同一个位置：网络断了时顶部横幅消失、状态文字一闪而过，用户看到的是「没有问题」。 | 设置页 / 更新横幅 | R1 | 更新这条线在规范里只被约束了「不能弹窗打断录音」，没人问失败时用户看到的是什么。 |
| C-032 | 用户手动点过的白板档位被记住了，但这份记忆是整个应用一份、不是每场会议一份。换一场会议、或另一台设备打开时，会落在别人（或上一次）选的那一档上。 | 会议白板标签栏 | R1 | 规范要求「用户手动点过的档要照做」，规格方会照这条验收；没人问这份偏好该记在哪一层、跨会议对不对。 |

## 视角四：跨边界

| 编号 | 能力问题 | 产品入口 | 风险 | 它推广自哪一条 / 为什么规格方容易漏 |
|---|---|---|---|---|
| C-033 | 用户点更新横幅、下载安装完成之后应用自动重启：正在录的会议被打断，而且安装前没有任何地方告诉他「你现在正在录音」。 | 更新横幅 + 录音中 | R3 | 规范只写了「更新提示不能弹窗打断录音」（指别挡路），规格方会认为这条已满足，不会走到「安装本身会重启」这一步。 |
| C-034 | 清除历史会把所有日期、所有会议的逐字稿一起删掉（不只是今天），而白板里已经保存下来的 AI 正文留在原处：那些会议在白板的会议列表里消失，正文还在电脑上，界面上再也找不到入口。 | 设置页清除历史 → 会议白板 | R3 | 按钮文案是「清除全部历史记录」，听起来只关乎「记录」。没人想到白板的场次列表是靠这份记录撑起来的——删了记录，等于删掉了通往已保存正文的路。 |
| C-035 | 「恢复默认」没有二次确认，而且立刻写盘（不像旁边两颗按钮那样等「保存」）：用户在这张页里点一下就丢掉自己攒的纠错词表、两份应用名单、AI 配置和录音参数。 | 设置页底部 / 语音指令页底部 | R3 | 规范只要求「清除历史 / 清除所有数据」要二次确认，「恢复默认」被当成了一个无害按钮，从来没被归进破坏性操作。 |
| C-036 | 用户点了「恢复默认」再点「取消」——改动依然生效，因为取消只是把这一页关掉。用户以为「取消」能兜住，实际兜不住。 | 设置页底部 | R3 | 同一栏三颗按钮被当成一家人（保存 / 取消 / 恢复默认），规范只描述了它们各自做什么，没人验证过它们的心智是不是一致的。 |
| C-037 | 同一份用户数据被两个应用实例同时使用：开发模式下跑着一个、装好的应用也开着（或桌面版和浏览器版同时开着）。两边的录音都往同一份记录里写、设置互相覆盖，记录会混在一起。 | 任何界面（双开时） | R3 | README 里写着「开发前请退出已安装的 APP」，那是写给开发者的；规格方按「用户只开一个」的前提扫，不会问双开时用户会看到什么。 |
| C-038 | 浏览器版没有系统级能力：自动粘贴按名单判断时拿不到「现在最前面是哪个应用」，名单非空时字一句都不会粘出去。用户在浏览器里明明配好了名单，却什么也不发生。 | 浏览器版 · 底栏开关与名单 | R2 | 代码注释里写了「网页版没有系统级能力」，产品文档没把它翻成用户话；而规范把浏览器版列为「调界面时的备用」，规格方会顺手跳过它的功能行为。 |
| C-039 | 应用没开着的时候，语音指令、自动粘贴、全局热键全都不存在；外部 AI 助手却仍然能读到记录，还可能告诉用户「说完就自动粘过去了」。 | 主界面 / 外部 AI 助手 | R2 | 产品一边强调「应用不开也能读」，规格方容易把「能读」顺延成「能用」，两种能力在清单里长得太像。 |
| C-040 | 仓库里的代码和装好的应用里真正在跑的后端可能不是同一个版本（改完后端必须重新打包才会进 App）：表现是界面点了没反应、或某个功能直接说「找不到」。 | 装好的应用 | R2 | README 记过这条事故，但末尾那句「必须重新打包」是写给开发者的；产品清单里没人问「用户或开发者怎么发现自己正在用旧后端」。 |
| C-041 | 白板被投屏给一屋子人看、主界面被挡在后面时，白板上没有任何地方能看出「现在有没有在录、录了多久」。唯一的录音证据在另一个窗口里。 | 会议白板（投屏时） | R1 | 规范把白板定义成「新开一个独立窗口，和主界面并存」；规格方会照这条验收并存，不会问「只剩白板一个窗口时，状态还在不在」。 |
| C-042 | 白板在外接大屏 / 投影仪上打开（系统缩放和像素密度与笔记本不同）时，字号和布局是否还成立未知：机械巡检只按固定的几个像素宽高跑。 | 会议白板（外接屏） | R1 | 检查覆盖了三种宽高组合，规格方看到「已覆盖多视口」就会认为尺寸这条守住了，不会问「同一个界面在不同缩放比的大屏上」。 |
| C-043 | 系统对辅助功能的授权是跟着应用身份走的：应用更新之后这项授权可能失效，用户开着自动粘贴却不出字，而且不会收到任何新提示。 | 底栏自动粘贴开关 / 更新后 | R2 | 权限问题被默认归到「系统设置里的事」，不在产品清单的视野里；而它恰恰是「开关说开着、字出不去」这类事故的另一个来源。 |

## 待审查：无产品入口的能力

> 以下几条找不到「用户在哪个界面、做什么操作」的入口，或影响只在后台规则里体现，单独列出，不混进正式清单。

- **时区与跨零点**：记录按本机日期分文件，统计按浏览器本地日期归集。用户出差换时区、或一场会跨过零点录制时，记录会归到哪一天，界面上没有任何地方能看出来。触发它不是某次点击，而是一次时区变化。
- **升级时的配置格式迁移**：早期版本的配置格式与新版本不同时，用户升级后设置会不会被重置、会不会有提示，找不到入口观察（README 里提到的那个配置迁移模块在当前代码里已不存在）。
- **记录文件与白板场次的耦合**：白板的「一场会议」是从记录文件的存在和间隔反推出来的，不是一份独立保存的数据。这份耦合的入口在外部 AI 那一侧，界面上看不到。
- **录音中途改灵敏度/静音超时是否即时生效**：规范说音量条可以在开会中直接拖，但改完之后对当前这一场是否立刻起作用、要不要重连，界面上没有反馈点。
- **刚写入但还没进会议摘要的内容能否被搜到**：外部 AI 写进来的最新内容，在会议下拉的搜索里是否立刻可见、可搜，没有明确的界面入口来验证。
