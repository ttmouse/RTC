## 为什么

用户原话（2026-09-19）：「我觉得顶部的这一排 icon 的样式要优化一下，悬停之后呢，是可以给一个
浅色的背景色的。」

三个理由按重要程度排：

1. **一排六个图标，鼠标扫过去时不该整排都在闪红。** 悬停是「鼠标现在在哪一个」的提示，
   用唯一强调色表达这件事，等于让最频繁的反馈持续消耗稀缺色（接 D-002 的同一判断）。
2. **悬停反馈原来是「图标变红」，只在字形上体现。** 图标一多，字形变化比整块底色更难一眼扫到；
   给底色是让命中区域整体亮起来，读起来更快。
3. **底色只比页面底色深一点点**（`--paper-2`），作用是「鼠标在哪」而不是「这是个按钮」——
   所以不用边框、不用阴影、不做按下的立体感。

## 顺带修掉的分叉

统计（`#statsBtn`）和推荐（`#shareBtn`）原本各写了一套和 `#searchBtn/#cmdBtn/#meetingBoardBtn/#settingsBtn`
一模一样的盒模型，加上新来的搜索图标就是三套。本次合并成**四段共用规则**：
盒模型 / svg 尺寸 / 悬停 / 键盘焦点，六个按钮共用。新增顶栏入口要加进这四段，否则又会分叉——
这个坑已经被踩过两次（白板图标漏在规则外长成「贴歪的方块」；统计与推荐各抄一套）。
`#statsBtn` 只保留自己的字体（它多带一个今日条数），`#shareBtn` 只保留 `.on`（面板开着时图标转红）。

## 验证

已核验（2026-09-19），灯在同一脚本上（`npm run check:search`）：

```
搜索入口巡检：19/19 通过            # 其中一条：悬停：六个顶栏图标都是浅纸底 + 墨色图标
$ node tests/search-toggle.browser.mjs --break=hoverred   # 故意把悬停改回「无底色 + 印章红」
搜索入口巡检：18/19 通过 → 自证通过：让 1 条变红
```

断言逐个 `hover()` 六个按钮，比对计算出的背景色与文字色（必须等于 #ece4d4 / #1a1611），
只验一个是不够的——这一排的价值就在「整排一致」，漏掉的那个会自己长成例外。
