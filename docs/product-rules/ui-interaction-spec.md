# RTC 界面体验规范

> 这份文件写的是：**界面应该给人什么感觉，哪些交互是刻意这么设计的**。
> 每条里的「错误做法」都是已经踩过的坑，不要重犯。
> 技术实现约束在文末《实现约束》里，产品同学不用看。
>
> 最后更新：2026-09-19 ｜ 对应版本 v1.0.35

---

## 1. 外观：纸和墨

**要的感觉** 像一张纸，不像一个后台管理系统。

- 底色是米黄纸色，文字接近墨黑，只有**一个**强调色：印章红。
- 印章红只用在三处：录音中的圆点、输入光标、鼠标悬停和键盘焦点的提示。**别的地方不要用**，用一次就不珍贵了。（顶栏那一排图标自己卡例外：悬停给浅色底、聚焦用偏灰，两样都不占红，见第 2 节）
- 图标一律用线条图标（内联 SVG）。**不许用 emoji**。
- 字体是等宽字体（像代码字体那样的等宽字），到处统一。

**不要做** 引进第二种强调色、大圆角卡片、渐变按钮、阴影堆叠、emoji 图标。

## 2. 状态必须真实

状态区（底部电平尺一行的右侧）只有八种说法：**就绪 / 识别中 / 录音中 / 正在连接 / 服务未连接 / 模型服务未启动 / 麦克风不可用 / 没有声音输入**。

**为什么多一个「没有声音输入」** 前七种说的都是「服务这一侧好不好」，唯独没有一句话能描述「服务都好，但麦克风一个采样都没进来」——而这正是合上盖子再打开之后最常见的坏法：WebAudio 会话在睡眠里被系统打断、或麦克风设备换了/没了，水管断了但两端都亮着灯，界面照样写「识别中」。判据只认结构性的事实：**录音时麦克风回调停了**（三秒一次都不来），不是「安静」——用户不说话是正常的，那种情况仍然是「识别中」。它排在「识别中」之前显示（告警色），因为此时用户说的每个字都不会被存下来，比任何服务状态都紧急。

对应的两个动作都不许省：**能救就先救**（重新取一次麦克风、把音频会话拉回 running，这是自动的），**救不回来就如实说**，并且带一句下一步（点录音按钮停一下再开一次；还不行就退出重开应用）。同上一条约束：承诺的动作必须真的有用——「停止再开始录音」走的确实是重新取麦克风与新开音频会话的同一条路径。

**为什么在底部而不在顶部** 「录了多久」「识别中」说的是录音这件事本身，紧挨着录音按钮和两个开关，视线不用在窗口两头来回跑；顶栏那行只留标题和两个入口图标。

**硬约束** 空闲状态 + 服务连不上时，**不许显示「就绪」**。这几个字是用户判断"能不能放心开录"的唯一依据，说错一次就是一次数据丢失。

**「服务未连接」和「模型服务未启动」是两件事，不要合并**：前者说的是程序自己的服务（8931）没在跑，后者说的是本地引擎要用的模型服务（8933）没在跑——本地识别真正依赖的是后者，所以两个都得说。

选本地引擎时，模型服务就是「能不能录」的前提，不能只当它是设置页里的一条配置状态。它没起来时：主界面状态区说**模型服务未启动**（告警色），并带一句悬停提示指向设置页的「识别方式」；点录音会被一句话拦下，而不是让用户对着这行字空等 15 秒超时。百炼引擎不依赖它，此时不报这个异常。

**异常状态必须带下一步，而且承诺的入口要真的在** 模型服务没在跑时，设置页「识别方式」里必须给出：**原因**（服务自己的日志尾部翻成人话；认不出来的如实回最后一行，不许编）+ **一个真能用的动作**（「重启模型服务」，走 Tauri 命令 restart_local_asr）。开发模式复用了终端里的服务时，如实说明「请到启动它的终端里重启」——不去 kill 不属于本应用的进程，也不摆一个点了只会报错的按钮。服务自己回来（或又挂掉）时，开着的那一页不能停在旧结论上：探测结论一变就重渲染。

**同源约束** 设置页引擎行上的「使用中 · 模型服务未启动」和主界面状态区说的是同一次探测的结论（探测在 `src/js/model.js`，两边都走 `probeModelService`）——不允许两个页面各自探一次、各说各话。

异常状态用告警色（浅红）区分，不用新配色。

**睡眠唤醒是状态诚实的一个特殊考验** 系统睡眠会掐断的东西（音频会话、麦克风句柄、ASR 的 TCP 连接）都不报错，它们的共同点是「看起来还开着」。所以本应用在唤醒时会主动做两件事：立刻重探两个服务（而不是等下一次 60 秒校准，旧结论就是假状态），正在录音则重建音频输入并重开连接。浏览器不给 `lid` 事件，唤醒是靠「自己的定时器跳了几十秒」认出来的——这是启发式，窗口被完全遮挡时也会误判，所以唤醒动作必须便宜且幂等。

### 搜索入口：一个图标，不是一行常驻输入框

搜索框不再常驻。**理由是使用频率**：翻旧记录是低频动作，而一条常驻输入框等于天天在邀请人去搜索——主界面的第一眼被一个不常做的事占着。现在顶栏只有一个放大镜图标（和其它入口同尺寸、同线条、共用盒模型），点它才展开那一行搜索框、光标直接落进输入框。搜索能力一条没少，只是从「常驻一行」改成「按需展开」。

- **收起时必须连带清掉关键词**。否则列表会继续被一份看不见的过滤条件压着，用户看到的是「我的记录怎么少了一半」。关键词还在时输入框本身是可见的，状态从不偷偷存在。
- **Esc 一步一跳**：有词先清词（框留着），词空了再按才收起。一下把关键词和搜索框一起弄没了，用户分不清自己刚按了什么。
- **聚焦的边框用偏灰的墨色（`--ink-faint`），不用印章红**。这个框是点开才出现的，一打开就亮一道红太吵；聚焦要看得见只需要「比默认边框 `--rule` 明显深」这条。
- **不要做**：把它做回常驻输入框（或再加第二行）；在图标上叠角标、彩点提示「有过滤条件」；给展开状态加自动收起的定时器——搜索是用户自己点开的，什么时候关由他说了算。

展开状态挂在 `body.search-open` 上，**不写内联 `display`**：设置页 / 语音指令页「整页打开时把主界面让开」用的是内联值，两套写法会互相覆盖。

**守门检查** `npm run check:search`（19 条，跑真浏览器）。上面这几条行为读代码看不出来，所以别只靠肉眼：`--break=visible|hidden|red|hoverred|esc` 会故意卸掉对应实现，检查必须变红——不自证过的灯不算灯。

### 标题栏统计入口

标题栏不新增独立的一行统计区。在「实时逐字稿」标题与现有入口图标之间，放一个与其它入口同尺寸、同线条风格的统计图标和**今日记录总数**；数字随新记录实时更新，点击图标或数字打开独立统计页。统计页使用和设置 / 语音指令一致的整页形态，默认展示全量数据，提供记录条数、文字数、活跃天数、目标应用、识别引擎、按小时分布，以及固定最近 14 天的每日分布等维度。统计入口要可感知，但保持轻量，不能抢录音主流程。

### 会议白板入口

「语音指令」和「设置」中间是**会议白板**入口，用一块带支架的幕布图标——它表达的是「会上给大家看的那块板」，不是「某个应用的窗口」。点它**新开一个独立窗口**，和主界面并存：白板是要投给会议室里所有人看的，不能盖住主界面把正在录的东西藏起来。

**风格是硬约束** 顶栏那一排图标（统计 / 推荐 / 搜索 / 语音指令 / 白板 / 设置）共用四段规则：盒模型（无边框、常态无底色、15px 线条、4px 圆角）、svg 尺寸、悬停、键盘焦点。**新增入口时把这四段都加上**——这一条被漏过两次：白板图标当时没进规则，浏览器给了它默认的浅灰底和系统边框，夹在语音指令和设置两个无边框图标中间，看着像个贴歪的方块；后来统计和推荐又各写了一套一模一样的盒模型，改一处就漏两处。

**悬停给一层浅色的纸底（`--paper-2`）、图标转墨色，不再变印章红。** 一排六个图标，鼠标扫过去时不该整排都在闪红；红是稀缺色（见第 1 节），留给键盘焦点、录音中的圆点和输入光标。悬停的底色要比页面底色只深一点点——它的作用是「鼠标现在在哪一个」，不是「这是一个按钮」。

**宽屏的会议列表** 当窗口宽度达到 1000px 时，会议列表默认作为左侧侧边栏打开，和正文并排，不遮挡白板内容；顶部的列表按钮可以收起或重新打开。窄屏保留下拉菜单形态，避免列表挤压正文。侧边栏内搜索框固定在上方，会议列表独立滚动。

## 3. 列表永远不要「抢」用户的滚动

这是被反复调过的地方，三个规则都是刻意的：

1. **只在用户本来就贴着底部时**，新内容才自动跟在后面。
2. 用户一旦往上翻（哪怕只翻了一点），就**绝不**把他拉回底部；离开底部较远时才浮出一个「回到最新」按钮。
3. 往列表顶部插入更早的记录时，**视觉位置必须停在原处**，不能跳一下。

**错误做法的后果** 用户正在看 10 分钟前那句话，被新内容一脚踹到底部——这是最让人恼火的体验之一。

### 时间戳按微信式规则分组

后台保留每条记录的完整精确时间，前端不逐条重复展示：同一天内从上一次已显示时间开始计算，5 分钟内的连续消息不重复显示；达到 5 分钟或跨天时，在列表中间插入新的居中时间分隔条，并从这条重新计算。时间分隔条独立于消息，不按目标应用切换额外插入时间；目标应用图标放在每条内容左侧，表达这句话的去向。

### 悬停色块要托住内容，不能切着内容

鼠标停在一行上时，整行浮出一层很淡的圆角色块（意思只有一个：**这一行可以点，点了是复制**）。色块比内容宽——左右各留 12px，让应用徽标和文字不贴着色块边缘。

**为什么这件事值得写进规范** 色块原来和内容一样宽，上下有 8px 留白、左右是 0，应用图标正好被色块边缘压着切掉一角，看着像渲染坏了。悬停态是用户唯一能看出「这行可点」的线索，它长得像个 bug，这条线索就白给了。

**做法是「内边距 + 等量负外边距」成对出现**，内容位置一个像素都不动（应用徽标仍然和顶栏标题、底栏控制区在同一条竖线上），只有色块自己向两侧各长出 12px。**不要只写内边距**：那会把整列记录往右推 12px，和顶栏错开。

## 4. 边听边出字的感觉

- 还没定稿的话：斜体、浅墨色、末尾一个红色闪烁竖光标。
- 同一句话定稿时：**原地**从斜体变黑字，**不会多出一行**。
- 打字是顺着往下走的，不要做逐字动画或打字音效。

## 5. 复制有三个入口（都保留）

1. 点某一行 → 复制这一行，同时那一行有一下淡淡的红闪（作为"复制成功"的反馈，不用弹提示）。
2. 用鼠标选中任意文字 → 自动复制选区。

## 6. 底部控制区：常用操作不进设置页

- **音量条本身可以拖动**来调灵敏度——开会中觉得老断句，直接拖，不用打开设置。
  设置面板里没有这个选项，所以调法只能靠悬停提示说清楚（刻度是什么意思、往哪边拖更敏感）。
- 引擎下拉里，**用不了的引擎直接不显示**，而不是灰着放那儿（没配 Key 的百炼、没下模型的 Qwen3 都不出现）。
- 中间是大圆形的录音/停止按钮，不写字，文案放在鼠标悬停提示里。
- 主界面激活且未操作输入框、设置页、指令页、统计页或其它弹层时，按**空格键**切换开始/停止录音；快捷键复用录音按钮的同一套状态与失败处理，不改变录音逻辑。
- 电平尺那一行的最右侧是**状态区**（点 + 说法 + 时长）：录音中显示本次录音时长，空闲时显示本地服务运行时长。它和录音按钮同处一块区域，所以「在录没在录、录了多久」一眼能看到。
- 右侧两个开关（自动粘贴、自动回车）必须满足两条：**有提示音**、**有快捷键提示**。这两个开关会直接改变"话会跑到哪里去"，不能悄悄切换。它们是**总闸**，具体在哪些应用里生效由设置页的两份名单决定（见下）。

**每行记录左侧标出说话时的前台应用**：应用图标紧跟在内容左侧，表达「说这句话时用户正在使用哪个应用」，不再把它误读成粘贴去向。
- **文本颜色单独表达粘贴状态**：执行了自动粘贴，正文保持深灰；识别到了但没有执行自动粘贴，正文使用近灰色。暂不增加第二个状态图标。
- **两个事实分别保存**：事件中的 `activeApp` 是说话时的前台应用快照，`pasteStatus` 是自动粘贴结果；旧事件没有 `activeApp` 时不擅自补造历史。
- **同一句在「刚说完」和「重新打开之后」必须长得一样**：实时记录和历史记录都读取这两个字段，应用图标统一走 `src/js/pastebadge.js`。
- 为什么要标记：2026-09-18 用户配好名单后一直看不到效果，而「没粘」当时是**完全静默**的，他只能猜。
- **两个开关左边留一个很小的图标，表示「最近一句字去哪了」**：目标应用图标（粘出去了）/ 「送出」箭头（粘出去了、但拿不到图标）/ ⊘ 标记（没粘），三者都是 18px、半透明（很弱），悬停才出文字：`最近一句 · 已粘给 微信`、`最近一句 · 没粘 · Dia 不在名单`、`最近一句 · 没粘 · 认不出目标应用`；**空闲时整格不出现**。
  **为什么不用一行字**：一行文字会在同一位置轮流说「规则」和「结果」两件事（空闲摆名单、定型后报结果），看着别扭、也占地方；图标一眼能认（比名字好认），又弱到不抢注意力（用户原话：「能用一个很弱的方式吗？……就体现这个应用的图标」）。
  这一格是 2026-09-18 的事故留下的：用户配好名单后一直看不到效果，界面却一个字都不说，他只能猜。两件事必须分开说：**不在名单**（自己配的规则，他能改）和**认不出目标**（环境问题，多半是说话时最前面的是本程序自己）——别合成一句「粘贴失败」把人带偏。详见 `src/js/pastehint.js` 文头。

## 7. 设置是「一页」，不是弹窗

- 打开设置是**整页盖住**主界面，不是浮出一个小窗口。
- 每个设置项下面要写清**「什么情况该往哪调」**，而不是复述参数名。比如静音超时写的是「一句话被中途截断就调高，说完等太久才出字就调低」，而不是「静音检测阈值（毫秒）」。
- 底部固定三颗按钮：**保存 / 取消 / 恢复默认**。保存 = 真正写进文件，取消 = 不写。
- 数据目录这类信息，必须同时给「在访达中显示」和「复制路径」两个动作，并提示配置文件里有 API Key「勿外发」。
- 「清除历史」「清除所有数据」必须二次确认，并明确写出**不可恢复**。

### 语音指令用同一个「一页」模式

右上角指令图标打开的不是小浮层，而是和设置页同一套整页界面（复用 header / body / footer 和保存 / 取消 / 恢复默认三键）。理由：这是一张要反复编辑的表，浮层里编辑表格迟早变成滚动地狱。

三块内容都是「说法 → 它做什么」的行：

- **打开应用**：目标**必须从系统应用列表里选**（按钮弹出可搜索的下拉）。列表给的是系统认的 `.app` 包名，手写「飞书」这类显示名会得到「应用不存在」——这是刻意约束，不要为了「让用户随便填」把输入框放开。
- **按键 / 功能 / 快捷短语**：同一套编辑行，右侧是固定动作或一段文本。动作按性质分两块摆——按键类（回车、上下箭头）是「替你敲一下」，功能类（会议总结）是「让 app 干一件事」。混在一处，用户会以为会议总结也只是个快捷键。
- **按键可以自己定，功能不行**：按键的值是一个按键表达式（`Enter`、`Meta+Shift+KeyK`），点右边能从常用键里挑，也能直接按键录下来（组合键同理）。功能类的值对应程序里的功能码，**不能改**——想加新功能得往 `actions` 表和 `FUNCTION_LABELS` 里添；所以功能块没有「添加一条」，目标按钮也是不可点的样式，别做成「点下去才知道不行」。录不到的只有「按的是哪个 ⌘」：这条发键通道发不出左右修饰键，录制时会合并成一个，**界面上必须写明**，别让用户以为录上了。

别顺手破坏的实现约束：

- **保存只提交改动过的条目**（前端算 diff → 按键更新），不做整表覆盖：界面开着时用户或外部工具改了 `commands.json`，那次改动不能被界面抹掉（对应原则 6）。服务端的合并语义表达不了删除，所以删除必须显式列出。

### 按应用生效的名单（自动粘贴 / 自动发送）

底栏那两个开关是总闸，具体生效在哪些应用里由设置页的两份名单决定：上面「允许自动粘贴的应用」，下面「允许自动发送的应用」。两份都是**加进来才生效**的白名单，名单外的应用**既不粘贴也不回车**，字只留在记录里。

- **为什么不合成一张表**：两个开关的结果不一样——不发送只是没按回车（字已经粘进去了），不粘贴是字根本没出手。分开列，用户改哪个就是改哪个；合成一张表会让人误以为「关了粘贴还能回车」。
- **名单为空 = 沿用旧行为**（所有应用都生效）。刻意如此：老用户不会因为这次改动突然收不到字。
- **名单里存的是 `.app` 包名**（系统应用列表给的稳定身份，如 `WeChat`），界面上显示的就是它，不要再改回手写显示名——同一次核对里前台查询给的是本地化显示名（`微信`），按名字相等判定会让用户「明明加了微信却什么也没发生」（真实事故，判定与注释见 `src/js/settings.js` 的 `appInList`）。
- **名单外的应用不粘贴时不给提示**（用户明确选的行为：字只留在记录里），所以「为什么这里没粘」只能靠这两行说明文字回答——说明文字不能省（对应原则 3：状态必须诚实可理解）。

## 8. 反馈：一句话就好，不要打断

- 一般提示是一行字，5 秒后自动消失，不弹窗、不需要点确定。
- 开关和录制按钮这类**状态切换的确认落在控件自己身上**：按下去的那颗按钮做一下短促的脉冲（缩放 + 一圈墨色环），不往页面顶部写一行「已开启 / 已关闭」。那行字离手指远，连续切换会在标题下方反复闪；脉冲只在状态**真的变了**时才出现（启动失败回滚不该给一个「成了」的动静）。环用墨色不用印章红——红色是「录音中」这个状态本身，不当装饰用。
- **白板同理，而且更严：说明只在「没内容」时写，位置在内容区底部。** 标签栏（顶部 Tab 区域）**只放标签本身**，不挂状态、不挂自我说明。「可直接编辑」「本地模型 · <模型名>」「未整理」这类字 2026-09-17 已按要求从标签栏撤掉：那行字在屏幕最上方、离内容最远，说的却是内容自己的事；而「能不能编辑」顶栏的「编辑」按钮已经在说，模型名属于内部实现。有内容的那一档就只给内容，空档才用一句话说清「在等什么 / 为什么没出来」（见 `ux-issue-log.md` UX-10）。
- 声音（开始录音、停止录音、开关切换）集中在设置里一个总开关控制。
- 开始录音的提示音要**在麦克风启动之前**响，否则提示音会被录进去变成一条识别结果。
- 更新提示用顶部横幅，带真实下载进度，**不能弹窗打断录音**。

## 附录：实现约束（工程维护）

> 这些数字和属性是刻意选的，改之前先读代码里对应的注释。

**颜色与字体** — 全部定义在 `src/css/style.css:1-6` 的 `:root`，**不要在组件里写死颜色**：
`--paper #f3ede2` / `--paper-2 #ece4d4` / `--ink #1a1611` / `--ink-soft #524b3e` / `--ink-faint #8f8572` /
`--rule #d4cbb6` / `--seal #bf3a1e`（唯一强调色）/ `--seal-deep #8f2a14` / `--radius 4px`。
字号阶梯：正文 `15px/1.7`（`.txt`）、时间戳 `10px`、分组标题 `11-12px`、页面标题 `15-16px`。数字时刻用 `font-variant-numeric: tabular-nums`。

**滚动阈值** — `ui.js`：贴底判定 `BOTTOM_SLACK = 40`、「回到最新」浮出 `JUMP_SLACK = 120`、顶部翻页 `TOP_SLACK = 120`。
顶部前插必须记录插入前后的 `scrollHeight` 差值并补偿 `scrollTop`（`setListTopHint` / `prependEntries` 的注释解释了为什么不能按提示条自身高度补、为什么贴底时不补偿）。滚动监听必须 `{ passive: true }`，翻页判断用 rAF 合并。

**电平尺刻度** — `state.js`：尺子范围 = VAD 阈值可调范围（`VAD_THRESHOLD_MIN/MAX = 0.001 / 0.05`），所以刻度能一路拖到尺子两端。
「画电平条」「画刻度」「拖动刻度反解阈值」「仪表读数」四处必须共用 `rmsToMeterPct` / `meterPctToRms` / `meterPctToDb` 这几个同源函数（dBFS 刻度，-60 ~ -26 dBFS）。
**不要退回线性映射**：满量程 0.01 的线性尺下，原始麦克风正常说话就顶格（用户看到的「声音稍大就 100%」），轻声则挤在最左边几像素里。

**声音仪表** — `meter.js`：电平表的手感（快起慢落 + 峰值保持 + 静音干净归零 + 等宽数字读数）全在这里，`audio.js` 只负责把每个音频块的 RMS 喂进来。
采样与绘制必须分开：音频回调约 11.7 次/秒（4096 采样 @48k），直接写 `width` 会一格一格闪，而这个频率又远不够 60fps——所以回调**只写状态**，DOM 写入集中在 rAF 里。
**`#levelMeterBar` 上禁止再挂 `transition:width`**：JS 每帧写 `width` 时，CSS 过渡会让每次写入都从「上一次的中间值」重新起步，显示值会恒低于真实电平且常年追不上声音。快起慢落由 `meter.js` 的包络（`ATTACK` / `RELEASE`）负责，CSS 不要再插一手。
峰值延迟条 `#levelMeterPeak` —— **从尺子左端铺到历史峰值，是第二条完整的灰色进度条**。实时红条在上层覆盖前段；红条回落后，灰条逐步露出并在峰值保持后慢慢回落。右端 `#levelMeterPeakCap` 作为峰值位置的封口。两条进度的宽度差表达「实时」与「延迟」的时间差；归零时 `left` / `width` / `opacity` 都要清，指数回落永远逼近而不到达，所以有 `ZERO_PCT` 夹断。

**电平条的染色必须跟着「画出来的电平」走，不能跟着瞬时 rms 走** —— 染色档位存在 `meter.tone`，由 `applyTone(level, tone)` 在 rAF 里按 `meter.level` 决定，并带 `TONE_HOLD_MS = 220` 的保持窗口。
**这是「红色实时条在收回途中变灰」的根因修复**：原先 `feedMeter` 直接按这一块的瞬时 rms 写 `bar.className`，声音一停，条还慢慢往回缩（宽 67%），颜色却已经瞬间翻灰——看起来就是「实时条正收回呢，颜色没了」。220ms 的窗口覆盖句间自然停顿（150~300ms），所以说话时不会红灰红灰地闪。

**电平尺内的三层 z-index 不能随便动**（`style.css`，从下到上）：峰值轨迹 `z-index:1` → 刻度 `z-index:2` → 条 `z-index:3`。
轨迹必须在刻度之下：它是半透明墨色，压过来会把刻度对比度从 5.19 拉到 3.07（低于 4.5 可读线），而刻度是拿来拖的控件。条必须在刻度之上：这是「冲过阈值后刻度反白」而不是「同色消失」的关键。改层级前先看 `#levelMeterBar` 上方的层级表注释。

**VAD 刻度必须分两层画** — `#levelMeterTick`（深红，条没盖住时可见）＋ `#levelMeterTickInv`（纸色反白，写在 `#levelMeterBar` **内部**，条盖住刻度时才露出来）。
**不要合并成一条**：曾经只有一条深红刻度压在条上面，电平冲过刻度、条变成 `loud` 深红之后，深红刻度压在深红条上**完全同色**——恰恰在最该看清「有没有超过阈值」的那一刻消失。
外层靠条的 `z-index` 压住、内层靠条的 `overflow:hidden` 裁切，所以「覆盖前深红 / 覆盖后反白」是纯几何结果，不需要 JS 判断；但内层的 `left` 百分比是相对**条宽**的，而刻度位置相对**整条尺子**，所以要 `tick / level × 100` 换算，由 `meter.js` 的 `syncTickInverted` 每帧摆。两层必须严格对齐（实测误差 0px），错开会出现双线。

**仪表不要用 CSS gradient**：规范第 1 节禁的是「渐变按钮」，但这里额外有一条技术理由——在每帧重绘的元素上铺 `gradient` 会让 WKWebView 把这块变成逐帧重算的渐变层（同下面「性能硬约束」）。仪表的所有层次都用纯色 / `rgba` 叠出来。

**性能硬约束** — 背景噪点与渐变两层必须 `position:fixed` + `transform:translateZ(0)` + `will-change:transform`（`style.css:14-16`）。缺了这三个属性，WKWebView 下每次滚动都会重绘整屏噪点，表现为卡顿。

**控件规范** — 图标内联 SVG，`24x24 viewBox`、`stroke-width:2`、`round` 端点（项目内 0 emoji）。**禁原生 `<select>`** 做浮层（WKWebView 弹层闪烁抖动），照 `.engineMenu` / `.engineOption` 写自定义下拉；设置页表单里的服务商下拉是唯一保留的原生 select。纯图标按钮必须同时有 `title` 和 `aria-label`。悬停提示统一走 `data-tip`（快捷键、电平尺刻度含义）；
用了 `data-tip` 的元素**不要**再设 `title`，否则系统提示会和这套 Tips 叠着弹。拖动电平尺期间 `#levelMeterBlock` 挂 `.dragging` 收起提示。`:focus-visible` 保留 `2px solid var(--seal)`。

**结构** — `.listWrap > main#list`；时间分隔条 `.timeSep` 独立居中；行 `.line > .pasteBadge + .txt`（去向徽标，见 `pastebadge.js`）；另有 `.daysep` / `.empty` / `#listHint` / `#jumpBottom`。设置页全页覆盖时把 `#queryBar`、`#list`、`footer` 全部 `display:none`。`#queryBar` 自己默认 `display:none`（`body.search-open` 才打开，见第 2 节「搜索入口」）——所以上面那两处写的是内联 `display:none`，收工时清空内联值即可，不要顺手把 `#queryBar` 的默认可见性改回去。Toast 统一走 `#err`（5s），不要为单个功能新建容器。音效集中在 `src/js/sfx.js`。

**HTML 注释必须闭合**（`npm test` 已加检查）——`src/index.html` 里的注释要用 `-->` 收尾，**不要**顺手写 CSS 的 `*/`。注释没闭合时解析器会一路吞到下一个 `-->`，中间的元素整段变成注释文本、DOM 里直接不存在，而页面**不报错**（真实事故：电平条、刻度、峰值线三个元素连同结构一起消失，测试全绿）。
