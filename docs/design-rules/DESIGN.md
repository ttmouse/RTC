## §1 视觉语言与定位

**主张**【项目】：界面像一张纸——底色是暖纸，文字是墨，印章红是唯一强调色。语音工具是常驻这两天瞄一眼的工具，视觉气质要"安静、像纸不像后台"，等宽字体是这一主张的一部分。
【基础】工具类产品界面服务于任务，内容优先，装饰克制。
**适用条件**：主界面所有可见元素（设置页/指令页/统计页/模态框同形态继承）。
**例外归属**：菜单栏与会议白板自有外观（§5-B / §5-C，均登记）。
**红色稀缺律（正本总纲）**：`--seal`/`--seal-deep` 只用于四处——录音状态点/录制按钮、打字机光标、`focus-visible` 焦点、错误提示。其余交互（悬停/激活/开关态）一律走墨色阶与 `--paper-2` 底色变化，不占红。
**判定方式**：人工（看图数红色出现在哪；npm test 的静态检查拦不住写死色值）。`style.css` 23 处 `:focus-visible` 已核对一致（2026-09-20）。
**反例**：顶栏曾把悬停做成红；新增第二个强调色属违规unless登记（D-5/D-6 待裁决）。
**忌讳**：大面积红色、彩色高饱和、渐变按钮、大圆角卡片、阴影堆叠、emoji 图标（项目内 0 emoji）。

## §2 颜色

【基础】颜色一律经变量契约引用，不写裸 hex；语义角色不复用。
【项目】色板（唯一来源 `:root`）：

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#f3ede2` | 页面底色（米黄纸） |
| `--paper-2` | `#ece4d4` | 次底：悬停底、浅色块、未选中标签底 |
| `--ink` | `#1a1611` | 正文与图标主色（墨） |
| `--ink-soft` | `#524b3e` | 次级文字：图标默认态、状态文字 |
| `--ink-faint` | `#8f8572` | 最淡一档：空态、提示、未激活刻度 |
| `--rule` | `#d4cbb6` | 分隔线、描边 |
| `--seal` | `#bf3a1e` | **唯一强调色**（印章红，稀缺律见 §1） |
| `--seal-deep` | `#8f2a14` | 异常态：服务未连接、麦克风不可用 |
| `--seal-light` | `rgba(191,58,30,.08)` | 印章红的淡底色：危险操作悬停、复制成功闪底（2026-10-01 补定义，见 §9） |

- 颜色**只在 `:root` 定义一次**，组件里不写死色值（主界面 token 化很干净：384 处 var，`:root` 外仅 25 处颜色字面量，多为墨色透明度变体）。
- **遮罩类**允许非 token（如 `rgba(0,0,0,.35)`），属内敛惰性使用，不确认为例外。
- **登记在案的未收敛色**（§5-C/D-5/D-6 过程中未裁决）：更新提示条黄色系、成功绿 `#3f6f4f`、Toast 淡红底 `#f3e3dc`、白板 `#c9a227`——.Write 都是"尚未登记偏差"→ 已通过本条补登记，处置见 §10。
**主题策略**【基础差异 D-2】：本项目**单主题**（纸墨亮色），不做 prefers-color-scheme。理由与反思记录于决策日志；若需暗色须先推翻此条并记录。

## §3 排版

**主张**【项目】：等宽字体栈全站统一（`--font`/`--mono`），"像纸不像后台"的一部分；层级靠字号与墨色，不靠加粗堆叠（字段标签刻意不加粗——加粗会和分区标题混淆）。
- 已确认的层级（正文中长期稳定）：逐字稿正文 `15px/1.7`；页面/区块标题 `15–16px`；分组与时间分隔条 `11–12px`；时间戳/统计数字 `10–11px`。
- **数值用等宽 + `font-variant-numeric:tabular-nums`**（时码、计数、进度），拖动滑块/滚动时数字不左右跳。
- **待收敛**（§10 D-3）：`style.css` 里 font-size 散着 8/10/11/12/13/14/15/16/18/20/22/30px 十二档（11/12px 频次最高）。新增字号时**优先复用已确认档位**，不为此单独发起重构。
**判定方式**：人工对照；tabular-nums 是否遗漏可 grep。

## §4 形状、图标与通用组件

- **圆角**：`--radius:4px`、`--radius-sm:3px` 为正本；胶囊类 `999px`。现存 2/6/8/10px 是历史遗留，改到附近代码时归 token，不单独重构（§10 D-3）。
- **图标**：一律内联 SVG，`24×24 viewBox`、`stroke-width:2`、`round` 端点（顶栏渲染为 17×17）。纯图标按钮必须同时有 `title` 与 `aria-label`。
- **提示**：悬停解释统一走 `data-tip`（纯 CSS，即时 0.12s）；用了 `data-tip` **不要**再设 `title`，否则系统提示叠着弹。
- **输入框**：底色必须比纸面深一档（--paper-2），只靠描边无法区分"哪里能写字"。
- **顶栏图标按钮**：六个入口共用同一套盒模型/悬停/焦点规则（§1 反例曾各自写一套改一处漏两处）——立规：**新增顶栏入口必须并入既有规则段，不许另写**。
- **音频电平尺**：条内分层 z-index 有详尽注释（色带 1 → 反白刻度 2 → 条 3），灯级条层级不得重排；被裁/被盖的检查属 `check:ux` 覆盖范围。
**判定方式**：图标规格可 grep；共用规则并入与否人工 review。

## §5 布局与例外表面

**A. 主界面**【基础】间距 4 的倍数档；对齐优先于填充。【项目】密度档偏密（4/5/6/8/10/12/16/18/20/24/32px）；列表行**无分隔线**（转写是连续口语流水，不是网格），悬停色块 padding 与负 margin 成对出现（内容不位移）。窗口最小宽 480px；底部三段式（左胶囊/中录制/右开关）。
**z-index 约定**【基础差异 D-1】：小数值阶梯 main=1 / footer=2 / tips=20 / menu=80 / contextMenu=120。基础层只约束"浮层压过页面元素"，本项目按实际规模拍数值，新浮层须压过 120。

**B. 菜单栏（macOS 层，不受 `:root` 约束——登记例外）**

| 项 | 值 | 说明 |
|---|---|---|
| 说话中底色 | `#FF9230` | 胶囊形，圆角取高度一半，画在系统按钮图层上 |
| 异常态 | `#D93025` | 麦克风/服务异常 |
| 格子宽度 | `28pt` | `TRAY_SLOT_WIDTH` 写死，防状态切换时旁边图标左右跳 |
| 字形画布 | `36×36`（18×18pt） | 全部字形画布一致，切换时视觉大小不跳 |

配色与形状由用户 2026-09-19 指定；**白色柱形压在 `#FF9230` 上仅约 2:1 对比度**——已知且被接受的取舍（D-4）。

**C. 会议白板（独立外观——待裁决 UX-4 / 基础差异 D-5）**
白板是独立 HTML 入口，不加载主界面 `:root`：底 `#faf9f7`、中性灰文字、第二强调色 `#c9a227`；`meeting-board/src/style.css` 写死颜色 89 处、共享 token 0 处。
**在裁决前，白板不算违规也不算合规**。它是投给一屋子人看的板，纯白高对比可以站得住（投影仪上纸色发灰）；裁决意见与改动前置条件见 §10 与 `ux-issue-log` UX-3/UX-4。

## §6 交互约定与动效

【基础】动效只在可用性上有意义时存在；reduced-motion 必须支持；高频数据更新不加过渡。
**项目层拍板**：
- 动效 token：过渡类 0.12s–0.22s，缓动 `cubic-bezier(.16,1,.3,1)` 用于位移/底色；`width .3s` 只用于真正的尺寸变化（进度、展开）。
- **动效不能撒谎（硬约束）**【基础差异 D-3 的一部分】：**每一帧由 JS 写入的属性，禁止挂 CSS `transition`**。电平条 `#levelMeterBar` 上禁止 `transition:width`——JS 每帧写宽度时过渡会让显示值从上一次的中间值重新起步，恒低于真实电平。快起慢落由 `meter.js` 包络负责，CSS 不插第二只手；**染色必须跟着画出来的电平走**（`meter.tone` + `TONE_HOLD_MS=220`），否则"红条在收回途中变灰"是说谎的动效。
- **状态必须真实（P2，最高优先，与其他规则冲突时赢）**：状态展示（就绪/录音中/服务未连接/说话中）必须与事实一致，拿不到事实宁可显示"不知道"，不许好看但假。判定方式：自动（`tests/main-status.test.mjs` 等 4 个测试，均在 npm test）。
- focus-visible 一律 `outline:2px solid var(--seal); outline-offset:2px`（全站 23 处一致）——红稀缺律第三位。
- 反馈落在动作发生的地方（P3）：状态与结果出现在用户刚操作过的位置附近，不让人去别处确认。
- 列表与浮层不抢用户的位置（P4）：新内容不顶走正在读的内容；悬停/浮层不盖住它要说明的内容；`overflow-anchor:none` 必须保留（翻页 scrollTo 补偿 与浏览器自动锚定会叠加跳视口）。
- 同一个决定只有一个来源（P5）：同一件事（颜色、圆角、提示样式、切分）只能一处定义别处引用；确有必要的局部覆盖要写注释说明为什么。
- `prefers-reduced-motion: reduce` 下关 animation（设置分组 sg-in、footerToggle 均已处理）。
**判定方式**：P2 自动（npm test）；P4 半自动（check:ux 几何量）+ 人工滚一次；P3/P6 人工（真机看）。

## §7 可读性与内容

**可读性是门槛，不是偏好（P7）**【基础差异 D-3 的另一半——本项目把"红线"升为正本】：
- 正文对比度 **≥ 4.5:1**，大号字 ≥ 3:1，可点区域 ≥ 16px，文字不许被裁。这不是外部标准，是项目自己把"色带压刻度把对比度从 5.19 拉到 3.07"当 bug 修过之后立下的线。
- **判定方式：自动**——`npm run check:ux` 用真实浏览器量对比度/可点区域/被裁被盖内容，新增可见元素时是最低门槛。
**内容**【项目】：中文为主；状态文字用白话（"模型服务未启动"），不说技术术语；空态用留白式（.empty 有 0.25em letter-spacing 的安静提示）；静默/空态不吓人、错误提示不吓人但要说清事实与下一步。

## §8 平台补充

【项目】主体是 **macOS Tauri 桌面应用**（WKWebView），Web 版仅为开发调试：
- WebKit 特有坑：button 文字须禁 user-select（拖选微动吞 click）；自定义 select 取代原生 select（Webkit 弹层闪）。
- 菜单栏相关改动（tray.js / lib.rs）属于本目录管辖，改动须过 §10 A 级门禁。
- `check:ux` 验的是 `dist/meeting-board`：改白板必须先 `vite build`，否则量的是旧构建（踩过）。保留 `prefers-reduced-motion` 支持。

## §10 治理：「改视觉要走什么流程」（与 governance.md 一体，冲突时以 governance.md 为准）

**四种真相，各有各的位置**：① 代码（`:root`/tray.js）＝数值实际是多少（唯一来源）；② 本正本＝应该长什么样、为什么；③ `../product-rules/ux-issue-log.md`＝发生过什么（台账）；④ `../evidence/`＝某次改动的检查证明。发现文档与代码不一致**不要悄悄选一边**，按 §9 登记。

**改动分级**：
| 级别 | 什么算 | 证据 |
|---|---|---|
| A：token 与全局规则 | 改 `:root`、改共用规则、改红的使用范围 | npm test + check:ux + 真机看主界面（菜单栏改动还要看菜单栏） |
| B：单组件/单页 | 调内距、字号、悬停色 | npm test + check:ux；改列表/浮层还要真机滚一次 |
| C：新增独立表面 | 新窗口/新页面/新样式入口 | 上述全部 + §9 留登记 + 用户确认 |

三条门禁：`npm test` / `npm run check:ux` / `npm run check:audio`（涉音频时）。
**批准边界**：Agent 可自行改"往规则收敛"的事（写死色换 token、新组件并入共用规则、修不达标对比度）；必须用户拍板的是会**改变用户看到结果**的事（改 token 值、引入第二强调色、新独立外观、接受不达标对比度）。
**回退**：样式集中在 `src/css/style.css` 与 `meeting-board/src/style.css`；改 token 后须**重跑** check:ux，对比度是算出来的。
