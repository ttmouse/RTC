# 设计原则

> **状态：已并入 [DESIGN.md](DESIGN.md)（2026-09-30），不再作为独立规则文档。**
> 本文件保留作历史参考；现行规则看 DESIGN.md 对应节，可判定书写格式已成为 DESIGN.md 全文统一格式。
写「优雅」「简洁」这类词在这里没有意义——判不了的原则不能当作修改依据。

判定方式一栏会明确写「自动」还是「人工」：**没有自动判定不等于不算数**，
它意味着这条改动必须有人在真机上看过（见 [治理合同](governance.md)，该格式已升级为 DESIGN.md 全文统一书写格式）。

## P1 纸和墨：底色是纸，文字是墨，强调色只有一个

- **主张**：界面像一张纸。印章红只用于录音中的圆点、输入光标、悬停与键盘焦点提示。
- **适用条件**：主界面所有可见元素。
- **反例**：顶栏曾把悬停做成印章红，红色被稀释；新增第二个强调色（白板的黄 `#c9a227`）属待裁决。
- **判定方式**：人工（看图 + 数一眼红色出现在哪）；`npm test` 的静态检查能拦住
  `style.css` 里的写死色值吗——**不能**，它只查括号与语法，所以这条必须人工看。
- **例外归属**：菜单栏与白板是登记过的例外（[DESIGN.md §5-B/C](DESIGN.md)）。〕
- **起因**：`ui-interaction-spec.md` 第 1 节；红色复用问题在 `style.css` 顶栏图标注释里记过一次。

## P2 状态必须真实：界面说的和实际发生的一致

- **主张**：任何状态展示（就绪 / 录音中 / 服务未连接 / 说话中）都必须与事实一致；
  拿不到事实时宁可说「不知道」，不许显示一个好看但假的态。
- **适用条件**：状态区、菜单栏、错误提示、模型服务显示。
- **反例**：睡眠唤醒后界面写「识别中」却一个采样都没出去（UX-14）；本机模型服务没跑，
  主界面照样说「就绪」（UX-11）；默认引擎下菜单栏永远不说「说话中」（附录里记过原因）。
- **判定方式**：自动（`tests/main-status.test.mjs`、`tests/tray-status.test.mjs`、
  `tests/tray-speaking.test.mjs`、`tests/audio-recovery.test.mjs`，均在 `npm test` 内）。
- **例外归属**：无。这是最高优先的一条，与其他原则冲突时它赢。
- **起因**：`core-product-principles.md` 第 3 条。

## P3 反馈落在动作发生的地方

- **主张**：状态与结果出现在用户刚操作过的位置附近，不要让用户去别处确认。
- **适用条件**：按钮、开关、粘贴结果、错误提示。
- **反例**：状态文字曾放在顶栏，离操作区很远；切换开关的确认曾往顶部写一行字。
- **判定方式**：人工（在真机上操作一次，问「不移动视线能不能知道发生了什么」）。
- **例外归属**：跨应用的反馈（如粘贴去向）允许落在记录行末，因为它没有更近的落点。
- **起因**：`core-product-principles.md`；`ux-issue-log` 中多条同类问题。

## P4 列表与浮层不许抢用户的位置

- **主张**：滚动位置属于用户：新内容不能把正在读的内容顶走；悬停/浮层不能盖住它要说明的内容。
- **适用条件**：逐字稿列表、顶部前插、下拉、悬停色块、提示条。
- **反例**：贴底与翻页阈值处理不当会把用户正在看的一行顶走；悬停色块切着内容显示。
- **判定方式**：自动（`npm run check:ux` 的「控件被盖住 / 内容被裁且够不着」）＋ 人工看滚动行为；
  阈值常量与补偿逻辑的实现约束见 `ui-interaction-spec.md` 附录。
- **例外归属**：无。
- **起因**：`ui-interaction-spec.md` 第 3 节；`style.css` 的 `.listWrap` 注释。

## P5 同一个决定只有一个来源

- **主张**：同一件事（颜色、圆角、提示样式、句子切分）只能有一处定义，别处引用它。
- **适用条件**：样式与前端逻辑都算。
- **反例**：顶栏图标盒模型曾被三个入口各写一套，改一处漏两处；`style.css` 里出现过一个
  没有选择器的声明块，浏览器静默吞掉紧随其后的整条规则（录制按钮退化成系统灰方块）。
- **判定方式**：自动（`npm test` 的静态检查覆盖「游离声明块」「HTML 引用资源存在」这类结构性事故；
  `check-ux.mjs` 用几何量判定视觉结果）＋ 人工（改样式前先找已有的四段共用规则）。
- **例外归属**：确有必要的局部覆盖要写注释说明为什么，不能只是复制一份。
- **起因**：`style.css` 多处注释；UX-6（标签宽度跳动）也是同一类病。

## P6 动效只解释变化，不掩盖变化

- **主张**：动画用来让用户看懂「刚才发生了什么」，不能用来拖住一个还没算完的状态，
  也不能让显示的数值与真实数值不一致。
- **适用条件**：电平尺、状态切换、列表插入、浮层出现。
- **反例**：电平条上挂 `transition: width` 会让红色条常年追不上真实电平；
  染色跟瞬时值走会出现「红条在收回途中变灰」。
- **判定方式**：人工为主（真机上看电平尺；这类问题在 headless 浏览器里复现不出来），
  已有 `tests/audio-recovery.test.mjs` 覆盖音频链路的结构性失效。
- **例外归属**：无。
- **起因**：`ui-interaction-spec.md` 附录的电平尺与 `meter.js` 注释（含根因分析）。

## P7 可读性是门槛，不是偏好

- **主张**：正文对比度 ≥ 4.5:1（大号字 ≥ 3:1），可点区域不小于 16px，文字不许被裁掉。
- **适用条件**：所有可见文字与可点元素，**包括白板**。
- **反例**：白板次要文字 2.42–3.10:1（UX-3）；主界面 `--ink-faint` 在纸色上 3.13:1（同一问题）。
- **判定方式**：自动（`npm run check:ux`，真浏览器量几何与对比度）。
- **例外归属**：菜单栏的白色柱形压在橙色上只有约 2:1，是**已知且被接受**的取舍；
  其余「故意做淡」的诉求，必须先裁决 UX-3（要么承认 4.5 线、要么从规范里去掉它，不能两边都要）。
- **起因**：`ui-interaction-spec.md` 附录自己写下 4.5 线，并在 UX-3 里被用来判定主界面与白板。

## P8 例外要显式登记，不能悄悄存在

- **主张**：任何偏离本目录规则的做法，必须在 [治理合同](governance.md) 的待裁决登记里
  有一行（现状、待谁裁决、裁决后写回哪里）。没登记的特殊做法按违规处理。
- **适用条件**：新增表面（新窗口、新页面）、新颜色、新动效模式、独立样式入口。
- **反例**：白板的独立配色存在了很久才被记为 UX-4，期间既没被当成违规、也没被当成决定。
- **判定方式**：人工（提交时对照登记表）。
- **例外归属**：这条本身就是例外的归属机制。
- **起因**：UX-4 的「要产品判断的」一段。
