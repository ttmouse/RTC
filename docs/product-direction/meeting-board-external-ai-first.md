# 会议白板：外部人工智能优先路线

## 一句话

应用负责记录、保存、动态加载和展示；外部人工智能负责理解会议、生成分析并写回文件。

## 为什么分阶段

先验证「会议记录 → 外部分析 → 白板展示 → 人工修正 → 文件保存」这条闭环，再考虑把稳定能力放回应用内部。这样可以先验证产品结构和数据格式，不提前绑定模型、服务商和调用方式。

## 当前阶段的边界

### 应用内部做什么

- 接收并保存逐字稿
- 读取白板数据
- 每 2 秒检查最新结果
- 展示会议定义和最新分析
- 提供 Markdown 白板编辑
- 保存人工编辑内容

### 外部人工智能做什么

- 推断会议背景、目标、角色和边界
- 分析当前话题、结论、待决问题和行动项
- 生成会议纪要
- 将结构化结果写入白板接口

应用当前不主动调用人工智能接口。

## 文件数据结构

白板数据暂时存放在应用数据目录的 `meeting-board.json`，包含：

- `definition`：会议定义
- `document`：人工维护的 Markdown 正文
- `analysis`：外部人工智能生成的最新结构化分析

后续稳定后可以拆为多个文件，但第一阶段先保持一个文件，便于验证闭环。

## 外部写入方式

外部工具先生成一个 JSON 文件，再执行：

```text
node scripts/meeting-board.mjs write-analysis <分析结果.json>
node scripts/meeting-board.mjs write-definition <会议定义.json>
```

也可以直接调用：

```text
PUT /api/meeting-board/analysis
PUT /api/meeting-board/definition
```

## 面板行为

白板打开时会按本地日期和连续转写之间的静默间隔整理会议场次：静默超过 5 分钟，就视为进入下一场会议。场次按钮显示在白板顶部，点击即可切换不同会议。

白板打开时先读取已有数据，之后每 2 秒自动读取一次。外部工具写入新分析后，面板自动更新，不需要刷新应用；新识别出的会议也会自动出现在场次列表中。

「读取最新场次」按钮用于人工立即重新整理一次。

外部工具写入指定会议时，在 JSON 文件后追加场次编号：

```text
node scripts/meeting-board.mjs write-analysis <分析结果.json> <会议场次ID>
```

场次编号由面板接口 `GET /api/meeting-board/sessions?date=YYYY-MM-DD` 返回。

## 后续阶段

1. 用真实会议记录验证外部分析结果。
2. 验证分析文件变化能稳定反映到白板。
3. 增加分析结果版本和来源标识。
4. 将人工正文、原始转写、分析结果拆成独立文件。
5. 只有重复、稳定、边界明确的能力，才评估是否内置人工智能。

## 验收标准

- 应用内没有主动人工智能调用。
- 外部写入分析结果后，白板两秒内能看到变化。
- 人工编辑正文不会被自动刷新覆盖。
- 重启应用后，定义、正文和分析结果仍然存在。
- 没有配置人工智能服务时，白板仍然可以正常打开和编辑。
