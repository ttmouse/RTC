# 手机逐字稿工具：iOS 产品方向

## 一句话

把 RTC 的核心能力收敛为一个只供本人使用的 iOS 实时逐字稿工具：启动后持续监听手机麦克风，将听到的内容实时转成文字；不保存音频，只保留逐字稿结果。

## 背景与目标

当前 RTC 已经具备本地 SenseVoice 实时转写能力。本方向不是重新做一个通用会议纪要产品，而是把“随身、持续、隐私优先的语音输入”迁移到手机上，服务于本人会议、访谈、学习和临时记录等场景。

首要目标：

- 打开应用即可开始实时转写。
- 文字低延迟地持续出现在手机屏幕上。
- 音频只在内存中经过处理，不落盘、不上传。
- 应用异常或停止后，用户仍能明确看到当前状态，不假装持续工作。
- 在没有 Apple Developer 身份的前提下，保留可通过连续签名安装和使用的现实路径。

## 核心使用流程

1. 用户通过连续签名安装应用。
2. 首次启动，申请并获得麦克风权限。
3. 用户点击“开始转写”。
4. 应用持续采集麦克风音频，送入 SenseVoice。
5. 实时展示识别中的文本，并按停顿自动分段。
6. 用户点击“停止转写”后结束本次会话。
7. 默认仅保存逐字稿文本；不保存原始音频。

## MVP 范围

### 必须有

- 麦克风权限申请与状态提示。
- 开始 / 停止转写。
- 实时文本展示，区分临时识别结果和已确认段落。
- 基于 VAD 的自动分段。
- 当前会话清空、复制和导出文本。
- 本地 SenseVoice 推理或与现有 RTC 本地 ASR 服务的明确连接方案。
- 无音频落盘的实现与可验证说明。
- 弱网或无网可用（如果模型能够随应用侧加载）。

### 暂不做

- 登录、多人协作、云端同步。
- 会议机器人或自动加入线上会议。
- 自动摘要、行动项提取、AI 纪要生成。
- 发言人识别和复杂多模态能力。
- 面向 App Store 的商业化发布流程。
- 后台无限时长运行承诺；先以 iOS 允许的前台 / 音频会话生命周期为准验证。

## 产品原则

1. **逐字稿优先**：先把实时转写做稳，不用摘要能力掩盖识别问题。
2. **隐私优先**：不保存音频；任何云端 ASR 都必须是显式可选项，不作为默认路径。
3. **状态诚实**：清楚显示监听、识别、暂停、权限不足、模型未就绪和错误状态。
4. **本人优先**：不为多人协作、账号体系和通用市场需求提前增加复杂度。
5. **可继续使用**：连续签名是当前安装约束，应用设计应支持重新签名后继续使用本地数据和配置。

## 技术方向

- **客户端**：原生 iOS 应用，优先 Swift / SwiftUI；音频采集使用 iOS 原生音频会话。
- **识别模型**：沿用 SenseVoice，优先评估 iOS 本地推理可行性；如暂时无法在手机端运行，再设计局域网连接 Mac RTC 的过渡方案。
- **音频管道**：麦克风 → 内存音频缓冲 → VAD / 重采样 → SenseVoice → 文本流；禁止将音频写入文件。
- **文本存储**：逐字稿可按会话保存为本地文本或 JSON；保存策略要能一键关闭或清除。
- **安装方式**：以连续签名为约束进行开发和测试，不把 App Store、团队证书或付费开发者账号作为 MVP 前置条件。

## 关键风险与验证顺序

1. **SenseVoice 能否在 iPhone 上稳定实时运行**：先做最小原生音频采集 + 单段推理原型，测延迟、耗电和内存。
2. **持续监听的 iOS 生命周期限制**：验证锁屏、切后台、来电和系统中断后的真实行为，不承诺未经验证的后台能力。
3. **连续签名可用性**：明确签名有效期、重新安装 / 重签名流程，以及重签名后本地数据是否保留。
4. **不落盘音频的证据**：通过代码路径审查、运行时文件监控和会话结束后的目录检查确认没有音频文件。
5. **手机端性能**：以真实设备为准，不以模拟器性能作为结论；至少记录端到端延迟、CPU、内存和电量变化。

## MVP 验收标准

- 在真实 iPhone 上，用户可完成“开始 → 连续说话 → 实时看到逐字稿 → 停止”。
- 连续说话时，确认文本延迟达到可用水平；临时文本不会反复大范围跳动。
- 应用运行目录和数据目录中没有生成音频文件。
- 无网络时仍能完成本地转写，或明确提示当前采用的 Mac 局域网过渡模式。
- 锁屏 / 切后台 / 系统中断的行为有实测结论，并在界面上诚实反馈。
- 通过连续签名安装后可正常使用；重签名不会要求重新配置核心设置，除非 iOS 机制确实如此。

## 后续演进

1. 先完成真实设备上的持续转写闭环。
2. 增加会话列表、文本搜索和 Markdown / TXT 导出。
3. 接入外部 AI，对用户主动选择的逐字稿生成摘要和行动项；AI 仍作为旁路，不阻塞转写。
4. 再评估跨会话记忆、快捷指令、Widget 和更深的 iOS 系统集成。
